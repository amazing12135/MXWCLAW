  问题 1：is_readonly 确认流程缺失，Runner 循环无法暂停等待用户

  分析：你说得对。AgentRunner 是纯引擎循环，内部 for 循环不能挂起等待外部用户输入。需要一个异步可恢复的确认机制。

  解决方案 — Bus 确认通道：

  # bus/messages.py 新增
  @dataclass
  class ConfirmationRequest:
      """Runner → Channel 的确认请求"""
      request_id: str
      channel: str
      chat_id: str
      tool_name: str
      tool_args_summary: str          # 工具参数的简短描述
      risk_level: str                  # "readonly" | "write" | "shell"
      timeout_seconds: int = 60

  @dataclass
  class ConfirmationResponse:
      """Channel → Runner 的确认响应"""
      request_id: str
      approved: bool
      reason: str | None = None       # 拒绝原因

  # bus/queue.py MessageBus 新增
  class MessageBus:
      _pending_confirmations: dict[str, asyncio.Event]
      _confirmation_results: dict[str, ConfirmationResponse]

      async def request_confirmation(self, req: ConfirmationRequest) -> ConfirmationResponse:
          """Runner 调用：发出确认请求并等待结果"""
          event = asyncio.Event()
          self._pending_confirmations[req.request_id] = event
          await self._publish_confirmation_request(req)  # 发给 Channel
          try:
              await asyncio.wait_for(event.wait(), timeout=req.timeout_seconds)
          except asyncio.TimeoutError:
              return ConfirmationResponse(request_id=req.request_id, approved=False, reason="timeout")
          return self._confirmation_results.pop(req.request_id)

      def resolve_confirmation(self, response: ConfirmationResponse):
          """Channel 调用：用户已做出选择"""
          event = self._pending_confirmations.pop(response.request_id, None)
          if event:
              self._confirmation_results[response.request_id] = response
              event.set()

  Runner 中的使用方式：

  # runner.py 中工具执行前
  if tool.is_readonly:
      # 只读工具直接执行
      results = await execute_tools(tool_calls)
  else:
      # 非只读工具 → 发出确认请求
      response = await bus.request_confirmation(ConfirmationRequest(
          tool_name=tool.name,
          tool_args_summary=str(tool.args)[:200],
          risk_level="write",
      ))
      if not response.approved:
          results = [ToolResult(error="User denied")]
      else:
          results = await execute_tools(tool_calls)

  确认超时兜底：超时视为拒绝，保障安全。

  问题 2a：JSONL Compact 破坏原子性

  分析：Compact 必须重写整个 .jsonl 文件，中途崩溃会丢失 Session。当前 Spec 只说"JSONL 追加写入行级原子"，与 Compact 行为矛盾。

  解决方案 — 临时文件 + 原子 rename：

  # session/manager.py
  class SessionManager:
      async def compact(self, session: Session) -> Session:
          """压缩 Session 历史，原子替换"""
          tmp_path = session.path.with_suffix(".jsonl.tmp")
          try:
              # 1. 写入临时文件
              async with aiofiles.open(tmp_path, "w") as f:
                  for msg in session.messages[-keep_last:]:  # 保留最近 N 条
                      await f.write(json.dumps(msg) + "\n")
              # 2. 原子替换
              os.replace(tmp_path, session.path)
          except Exception:
              # 3. 清理临时文件，原始文件完好
              tmp_path.unlink(missing_ok=True)
              raise
          return session

  Spec 修改：Session 安全设计改为：

  ▎ - JSONL 追加写入行级原子（日常追加）
  ▎ - Compact 使用临时文件 + os.replace() 原子替换（重写场景）
  ▎ - 任何异常原始文件完好，仅清理临时文件

  问题 2b：Provider 流式接口矛盾

  分析：3.2 节 chat() 返回 LLMResponse（含完整 content + tool_calls），但流式调用时 tool_calls
  是增量到达的，无法在调用开始时返回完整结构。两种模式必须分离。

  解决方案 — 双模式接口：

  # providers/base.py

  @dataclass
  class LLMStreamChunk:
      """流式响应的单个增量"""
      delta: str | None = None
      tool_call_delta: ToolCallDelta | None = None
      finish_reason: str | None = None

  @dataclass
  class ToolCallDelta:
      """流式工具调用的增量"""
      index: int          # 对应第几个工具调用
      id: str | None      # 首个 chunk 有 id
      name: str | None    # 首个 chunk 有 name
      arguments_delta: str  # 累积的参数 JSON 片段

  class LLMProvider(ABC):
      # 非流式 —— 一次返回完整结果
      async def chat(self, messages, tools) -> LLMResponse: ...

      # 流式 —— 返回 AsyncIterator，由调用方自行聚合
      async def chat_stream(self, messages, tools) -> AsyncIterator[LLMStreamChunk]: ...

      @abstractmethod
      def supports_streaming(self) -> bool: ...

  Spec 修改：
  - 3.2 providers 表增加 chat_stream() 抽象方法
  - LLMResponse 和 LLMStreamChunk 是两个独立的数据结构
  - Runner 中流式分支：async for chunk in provider.chat_stream(...) → 增量处理 + Hook.on_stream → 自行聚合 tool_calls

  问题 4：LoopPool vs Bus 职责归属模糊

  分析：当前 Spec 中 MessageBus.consume_loop() 混合了消息分发逻辑，Bus 应只是纯数据通道。

  解决方案 — 职责拆分：

  MessageBus（纯通道）:
    - input_queue: asyncio.Queue[InboundMessage]       # 入站队列
    - output_queues: dict[str, Queue[OutboundMessage]]  # 出站队列（按频道）
    - stream_channels: dict[str, Queue[StreamDelta]]    # 流式通道
    - confirmation_channels                              # 确认通道
    - publish_*() / subscribe_*()                        # 纯 I/O 方法
    - 不做消费、不做分发、不做业务逻辑

  LoopPool（消费 + 分发 + 并发控制）:
    - start() → 启动后台 asyncio.Task，循环从 bus.input_queue.get()
    - _dispatch(msg) → session_key → Semaphore + Lock → Loop.run()
    - max_concurrent: int = 20

  class LoopPool:
      def __init__(self, bus: MessageBus, ...):
          self._bus = bus
          self._semaphore = asyncio.Semaphore(20)
          self._session_locks: dict[str, asyncio.Lock] = {}

      async def start(self):
          """消费循环：从 Bus 取消息，按 Session 分发"""
          while True:
              msg = await self._bus.input_queue.get()
              asyncio.create_task(self._dispatch(msg))

      async def _dispatch(self, msg: InboundMessage):
          async with self._semaphore:
              session_key = f"{msg.channel}:{msg.chat_id}"
              async with self._get_lock(session_key):
                  loop = Loop(session_key, ...)
                  result = await loop.run(msg)
                  await self._bus.publish_outbound(result)

  Spec 修改：
  - 目录结构 bus/queue.py 去掉 consume_loop 描述
  - core/loop.py 增加 LoopPool 类的消费循环职责说明
  - 架构图 2.1 中 Bus 的 consume_loop 移动到 Core Orchestrator 的 LoopPool

  问题 5：流式异常中断时缺少 Channel 通知

  分析：LLM 流式输出中途出错，Channel 不知道流已中断，用户在 Channel 端看到消息断在半截。

  解决方案 — publish_stream_error：

  # bus/queue.py MessageBus 新增
  class MessageBus:
      async def publish_stream_error(self, stream_id: str, error: str) -> None:
          """流异常中断通知"""
          for ch_name, q in self._stream_channels.items():
              await q.put(StreamError(
                  stream_id=stream_id,
                  error=error,
                  timestamp=datetime.now(),
              ))

  # bus/messages.py 新增
  @dataclass
  class StreamError:
      stream_id: str
      error: str
      timestamp: datetime

  # channel/base.py
  class BaseChannel:
      async def send_stream(self, chat_id: str, stream_queue: asyncio.Queue) -> None:
          while True:
              item = await stream_queue.get()
              if isinstance(item, StreamDelta):
                  await self._send_chunk(chat_id, item.delta)
              elif isinstance(item, StreamError):
                  await self._send_chunk(chat_id, f"\n[响应中断: {item.error}]")
                  break
              elif item is None:  # stream_end 信号
                  break

  Runner 中流式异常处理：

  # runner.py
  try:
      async for chunk in provider.chat_stream(...):
          # 正常流式处理...
  except Exception as e:
      await bus.publish_stream_error(stream_id, str(e))
      raise

  问题 6：Heartbeat 明确为独立线程

  分析：当前写"独立线程/进程"，进程间通信复杂。明确为 threading.Thread 更简单可靠。

  解决方案：

  # heartbeat/scheduler.py
  class TaskScheduler:
      def __init__(self, storage: TaskStorage, bus: MessageBus, loop: asyncio.AbstractEventLoop):
          self._thread: threading.Thread | None = None
          self._storage = storage
          self._bus = bus
          self._loop = loop          # 主事件循环引用
          self._running = False

      def start(self):
          self._running = True
          self._thread = threading.Thread(target=self._run, daemon=True)
          self._thread.start()

      def _run(self):
          """后台线程：等待 cron 触发 → 通过 MessageBus 投递消息"""
          while self._running:
              due_tasks = self._storage.get_due_tasks()
              for task in due_tasks:
                  # 线程安全地投递到主事件循环
                  asyncio.run_coroutine_threadsafe(
                      self._bus.publish_inbound(InboundMessage(
                          channel="system",
                          chat_id=task.owner,
                          content=f"[Scheduled] {task.prompt}",
                          ...
                      )),
                      self._loop,
                  )
              time.sleep(1)

      def stop(self):
          self._running = False
          if self._thread:
              self._thread.join(timeout=5)

  关键点：
  - threading.Thread(daemon=True) — 主进程退出时自动终止
  - asyncio.run_coroutine_threadsafe() — 从线程安全投递消息到主事件循环
  - 心动任务投递为 InboundMessage(channel="system") — 复用现有消息通道，无需特殊路径
